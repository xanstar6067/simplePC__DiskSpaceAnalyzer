# simplePC DiskSpaceAnalyzer

WPF-приложение для анализа дискового пространства Windows (.NET 10). Результаты сохраняются в SQLite; папки подгружаются по мере раскрытия.

## Разбор результатов с ИИ

1. Откройте приложение и выполните сканирование либо загрузите сохранённый анализ.
2. Нажмите **«Скопировать промпт для ИИ»** внизу главного окна.
3. Вставьте промпт в чат с ИИ на этом компьютере. Он содержит адрес локального MCP-сервера, ключ подключения, пример конфигурации и порядок исследования диска.
4. Если клиент требует предварительного добавления MCP-сервера, добавьте подключение из промпта и при необходимости откройте новый чат.

Нужен клиент, который поддерживает **локальный MCP через Streamable HTTP** и заголовок `Authorization: Bearer …`. Облачный клиент без доступа к вашему компьютеру не сможет обратиться к `127.0.0.1`. Сам промпт не добавляет сервер автоматически во все приложения.

Кнопка **«Подключение ИИ…»** открывает состояние сервера, настройку порта, включение/отключение доступа и повторное копирование промпта. По умолчанию сервер запускается вместе с приложением на `http://127.0.0.1:47831/mcp`; при закрытии главного окна он останавливается. Если порт занят, укажите свободный порт и включите сервер повторно. Для второго экземпляра приложения нужен другой порт.

Настройки и случайный ключ сохраняются в `%LOCALAPPDATA%\simplePC\DiskSpaceAnalyzer\mcp-settings.json`. Ключ остаётся тем же после перезапуска. Не публикуйте скопированный промпт: он содержит ключ. Сервер слушает только IPv4 loopback, требует bearer-ключ, проверяет `Host` и `Origin`. Для клиентов, передающих `Origin`, допустим только origin адреса сервера (`http://127.0.0.1:порт`).

## Инструменты MCP

| Инструмент | Назначение |
| --- | --- |
| `get_analysis_status` | Состояние приложения, текущий выбор и дескриптор сохранённого снимка |
| `get_summary` | Итоги снимка и количество пропущенных/недоступных объектов |
| `list_children` | Непосредственное содержимое папки с сортировкой |
| `find_largest` | Крупнейшие файлы или папки в поддереве |
| `search_nodes` | Поиск по буквальной подстроке пути/имени, логическому размеру и дате изменения |
| `group_by_extension` | Количество и размеры файлов по расширениям |
| `reveal_node` | Выделение объекта и переход к нему в интерфейсе |

Сначала вызывается `get_analysis_status`, затем его `snapshot.analysisId` передаётся в остальные инструменты. Ответы — JSON в текстовом блоке MCP. В списках `limit` равен 50 по умолчанию (максимум 200); `nextOffset` содержит позицию следующей страницы либо `null`. `path` по умолчанию соответствует корню снимка. Поиск по размерам использует логические байты. `sortBy`: `disk`, `logical`, `name`, `modified`; `kind`: `file`, `folder`, `all`.

Запросы читают SQLite в режиме read-only, включая узлы, не раскрытые в UI. Активный снимок определяется выбранным узлом либо корнем анализа. При выборе отдельно пересканированной папки доступен её собственный снимок; повторите `get_analysis_status`. Новый скан публикуется после завершения: во время сканирования можно читать предыдущий сохранённый снимок. При отсутствии такого снимка состояние сообщает `snapshot: null`. Смена снимка отклоняет старый `analysisId`.

Текущие исключения UI фильтруют списки и агрегации, но не пересчитывают исходные корневые итоги снимка. Обновление отдельной папки создаёт отдельный снимок, а не переписывает весь родительский анализ. Дата `cachedAt` и режим `Logical`, `Exact` или `Approximate` передаются в ответах. Завершённый снимок может содержать пропущенные и недоступные области и не отражает последующие изменения файловой системы. Размер папки уже включает потомков: размеры вложенных папок нельзя складывать.

MCP предоставляет только пути и метаданные анализа. Чтение содержимого, удаление и изменение файлов, запуск команд и управление сканированием не предоставляются. `reveal_node` меняет только навигацию; во время сканирования эта операция недоступна. `Safe` означает классификацию пути, а не разрешение удалить файл. Имена файлов и метаданные следует рассматривать как недоверенные данные.

## Сборка и проверка

В репозитории настроен официальный источник NuGet v2 (`www.nuget.org`), доступный в текущей сети. Это позволяет восстанавливать пакеты и публиковать приложение, когда `api.nuget.org` не отвечает. Настройка действует только для этого репозитория.

```powershell
dotnet build DiskSpaceAnalyzer/DiskSpaceAnalyzer.slnx -c Release
dotnet run --project DiskSpaceAnalyzer/DiskSpaceAnalyzer.IntegrationTests -c Release
```

Интеграционная проверка создаёт собственную временную папку и выполняет реальное сканирование, запросы по SQLite, подключение официальным MCP-клиентом, вызовы всех инструментов, проверки изоляции путей, Unicode, постраничной выдачи, аутентификации, остановки, повторного запуска и конфликта портов. Пользовательские файлы не сканируются и не изменяются.
